# Воспроизводимые параллельные редукции

**Исследование компромиссов между точностью, воспроизводимостью и производительностью параллельных редукций на CPU и GPU.**

[English version](README.md)

`reproducible-reductions` — исследовательский проект на C++20, посвящённый сравнению нескольких подходов к редукциям чисел с плавающей точкой.

Это **не демонстрация одного выбранного алгоритма**. Репозиторий задуман как экспериментальная среда для реализации, проверки, измерения и честного сравнения разных стратегий редукции на разных наборах данных и аппаратных конфигурациях.

## Проблема

Сложение чисел с плавающей точкой не является ассоциативным:

```text
(a + b) + c != a + (b + c)
```

Параллельное выполнение меняет порядок объединения частичных результатов. Поэтому итог может зависеть от дерева редукции, количества потоков, планирования, оптимизаций компилятора, формата чисел и архитектуры процессора или GPU.

Проект исследует компромисс между тремя целями:

- **точность** — близость к эталонному результату повышенной точности;
- **воспроизводимость** — совпадение битового представления между запусками, конфигурациями потоков и архитектурами;
- **производительность** — задержка, пропускная способность, масштабируемость и использование памяти.

## Исследовательский вопрос

> Какую цену по производительности необходимо заплатить для достижения заданного уровня точности и воспроизводимости параллельных редукций?

Долгосрочный вопрос: может ли система автоматически выбирать подходящий алгоритм на основе характеристик входных данных, требований к точности и воспроизводимости, а также доступной архитектуры CPU или GPU?

## Исследуемые подходы

| Семейство | Планируемые методы | Цель |
|---|---|---|
| Базовые реализации | обычное накопление в `float`, накопление в более точном типе | получить базовые оценки скорости и ошибки |
| Структурированное суммирование | pairwise и древовидные редукции | улучшить численное поведение и использовать параллелизм |
| Компенсированное суммирование | Kahan и Neumaier | уменьшить ошибку округления |
| Детерминированные редукции | фиксированные деревья | обеспечить повторяемость между запусками и числами потоков |
| Воспроизводимые аккумуляторы | binned и exponent-aware подходы | получить более строгие гарантии воспроизводимости |
| Параллельный CPU | OpenMP и явные деревья редукции | исследовать масштабирование и влияние планирования |
| GPU | блочные и иерархические CUDA-редукции | исследовать пропускную способность GPU и порядок операций |
| Библиотечные baseline | оптимизированные CPU/GPU-библиотеки | сравнить свои реализации с промышленными решениями |

Ни один метод заранее не считается универсально лучшим. Цель — определить, какие реализации входят в Pareto frontier по точности, воспроизводимости и скорости при разных сценариях.

## Экспериментальные данные

Будут использоваться контролируемые наборы с разными численными свойствами:

- случайные значения;
- большой диапазон экспонент;
- чередование знаков;
- сильное взаимное уничтожение;
- сортировка по модулю;
- специально построенные сложные порядки;
- скалярные произведения и нормы векторов;
- данные из численных алгоритмов.

Эталонные результаты будут вычисляться с повышенной точностью.

## Метрики

### Численное качество

- абсолютная ошибка;
- относительная ошибка;
- ошибка в ULP;
- отклонение от высокоточного эталона.

### Воспроизводимость

- битовое совпадение повторных запусков;
- воспроизводимость при разном числе потоков;
- воспроизводимость при разных схемах планирования;
- позднее — воспроизводимость между CPU и GPU.

### Производительность

- задержка;
- число элементов в секунду;
- эффективная пропускная способность памяти;
- ускорение и эффективность параллелизма;
- накладные расходы относительно самого быстрого baseline.

## Методология

Эксперименты должны полностью воспроизводиться из кода и конфигураций репозитория. Будут раздельно измеряться:

- генерация входных данных;
- выполнение редукции;
- вычисление эталонного результата;
- анализ ошибки;
- время и аппаратные счётчики;
- экспорт CSV и построение графиков.

Для каждого результата будут фиксироваться компилятор, флаги, модель CPU/GPU, количество потоков, параметры набора данных, прогрев, число повторений и статистика измерений.

## Текущий статус

**Проектирование исследования.**

Первая фаза будет CPU-only и намеренно узкой: последовательные baseline, компенсированное суммирование, высокоточный эталон, тесты и воспроизводимые benchmarks.

CUDA, распределённые редукции и адаптивный выбор будут добавлены только после появления надёжной CPU-методологии.
